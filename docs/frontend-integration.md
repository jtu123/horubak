# 프론트엔드 ↔ 팀 기능 연결 제안

이 문서는 신규 연결 제안입니다. 구현 완료된 서버 API 명세가 아닙니다.

## 현재 경계

UI는 네트워크 요청 없이 개발용 저장소를 사용합니다. `store.tsx`의 데모 구현을 `services/contracts.ts`의 Gateway를 사용하는 서비스로 교체할 때 실제 API를 연결합니다. API 실패를 샘플 성공으로 대체하지 않습니다.

| 화면 | 연결 담당 영역 | //
|---|---|
| 로그인/회원가입 | 권준한: Spring Security, `/api/auth` |
| 목록·등록·원본 다시 연결 | 팀 프로젝트/미디어 등록·조회 API |
| 처리 상태 | 팀 작업 등록·상태 조회·취소·재시도 API |
| 후보·전사·맥락·추적 | 권준한 분석 모듈의 결과 조회 |
| 편집 저장·되돌리기 | 팀 편집 상태·버전 API |
| 결과·다운로드 | 팀 렌더 작업·파일 접근 API |

## 공통 데이터

- 시간: 원본 초 단위. SRT를 만들 때만 클립 상대 시간으로 변환합니다.
- 결과: 프로젝트 ID·입력 버전·분석 설정 버전을 연결합니다. 과거 작업 결과로 최신 편집을 덮어쓰지 않습니다.
- 작업 상태와 처리 단계는 별도 필드입니다. 상태는 `queued/running/completed/failed/cancelled`, 단계는 `preprocess/stt/candidates/context/tracking/render`입니다.
- 얼굴·크롭의 전달 좌표는 원본 기준 정규화 좌표로 변환합니다. 현재 UI의 `cropX/Y` 0~100 퍼센트와 `scale`은 **미리보기 조작 값**이므로 그대로 얼굴 검출 결과로 취급하지 않습니다.
- `completed`는 현재 브라우저 데모의 편집 검토 상태입니다. 실제 작업 완료 상태와 연결할 때 렌더 성공과 혼용하지 않도록 서버의 프로젝트 상태 계약으로 교체합니다.
- 전사 수정, OCR·레이아웃 추천, 자연어 명령 처리, 영상 렌더는 별도 기능 담당 구현을 연결합니다.

## 실제 인증을 연결할 때

브라우저의 사용자 ID·로컬 프로필은 권한 증거로 사용하지 않습니다. 서버 세션에서 사용자를 결정하고 프로젝트·원본·작업·편집·결과 접근마다 소유자를 검사합니다. 회원정보·프로젝트 영속 저장과 접근 제어가 연결된 이후에만 SIR-001 완료로 판단합니다.

세션 쿠키·CSRF 처리를 포함한 인증 API를 먼저 연결합니다. 실제 비밀번호·API 키를 브라우저 저장소·프론트 코드에 넣지 않습니다. 개발용 프로필 로직은 실제 인증을 켠 환경에서 제외합니다.

## 실제 원본을 연결할 때

현재 파일 선택은 브라우저 미디어 정보와 미리보기만 사용합니다. 확장자·파일 크기·브라우저 재생 확인은 서버의 위장 파일·미디어 검사·URL 허용 정책을 대체하지 않습니다. 원본 확보·저장은 팀 입력 API가 담당합니다.

내보낸 JSON의 `rendered:false`는 영상 미생성을 뜻합니다. `target`의 1080×1920·H.264/AAC는 출력 목표이며 생성 결과의 검사값이 아닙니다. 실제 렌더 성공·버전·ffprobe 검증 후에 MP4 다운로드를 활성화합니다.
