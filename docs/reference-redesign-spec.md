# 호루박 UI 참고 디자인 개편 명세

기준일: 2026-11-06. 참고: [FleetFlow AI 디자인 영상](https://www.instagram.com/reel/DfKk_35BP85/).
기존 기능 기준: UI v3 및 OpusClip 분석 후 후보·비율·redo 보완.

## 참고에서 가져오는 것

브라우저에서 대시보드와 승인 대화상자의 영상 장면을 확인했다. 밝은 회색 바탕, 흰 작업 표면, 좁은 아이콘 레일, 보라색 주요 행동, 연두색 상태 강조, 큰 요약 숫자와 작은 레이블, 얇은 구분선과 둥근 카드가 관찰됐다.

이를 영상 제작 작업공간으로 해석한다. 물류 지도·차량·배송 지표·참고 제품명과 자산은 사용하지 않는다. 보이는 화면의 미감을 참고하며 원본의 소스 코드·정확한 색상값·글꼴 이름을 확보했다고 주장하지 않는다.

## 디자인 계약

| Before | After | Why |
|---|---|---|
| 넓은216px 사이드바 | 기본76px 아이콘 레일, 필요하면 메뉴 펼치기 | 주요 작업 영역 확보, 참고의 탐색 밀도 적용 |
| 파란색 중심·푸른 포스터 | 보라색 포인트·중립 표면·연두 상태, 장르별 원본 벡터 포스터 | 참고의 색채 위계를 영상 제작 언어로 재해석 |
| 제목·최근 작업·카드 목록 | 인사/제목·실제 요약·최근 작업+안내·프로젝트 모음 | 현재 상태와 다음 행동을 한 화면에서 연결 |
| 페이지별 제각각인 카드 강조 | 얇은 테두리·절제된 그림자·일관된 모서리와 입력 스타일 | 로그인부터 결과까지 시각적 일관성 |
| 조밀하지만 위계가 비슷한 문자 | 제목30/38px, 본문13px 중심, 레이블11~12px와 숫자 대비 | 한국어 작업 화면의 가독성과 정보 위계 |
| 예시만 기존 파란색 | Stageshow 정적 제작 흐름도 같은 색 체계 | 실서비스 화면과 설명 그림의 시각 언어 일치 |

색은 측정한 원본 값이 아닌 호루박용 근사 팔레트다. 라이트는 따뜻한 회색/흰색/보라색, 다크는 숯색/옅은 보라색으로 해석한다. 성공·오류·경고의 의미와 문자·아이콘을 보존한다.

## 기능·화면 범위

데스크톱1280px 이상. 모바일 전용 화면은 만들지 않는다. 저장된 테마 선택과 사용자 자료는 유지한다.

- 전역: 레일·헤더·검색·계정·도움말·대화상자·토스트·키보드 포커스.
- 프로젝트: 실제 프로젝트/클립/즐겨찾기/연결 원본 요약. 임의의 AI 성과·처리량·매출 지표를 만들지 않는다.
- 등록: 실제 폼과 Stageshow 예시를 분리하고 서버 전송·분석 완료로 연출하지 않는다.
- 후보/편집/결과: 탐색·일괄 보관·맥락 보정·undo/redo·비율·가이드·다운로드의 상태와 의미를 보존한다.
- 라이브러리·작업·게시·팀·성과·설정: 같은 시각 체계를 적용하고 실제 미연결 기능은 미연결로 유지한다.
- 로그인/가입: 가운데 양식·입력 오류·비밀번호 보기·샘플 진입을 보존한다.

## 스킬과 작업 인계

Emil: 반복 조작·키보드·검색에 장식 애니메이션을 넣지 않는다. 포인터 피드백은 짧게, 모션 줄이기를 지원한다.

Lucian: 공식 CLI로 #040 사이드 레일을 검색하고 #040·#039 탭·#046 빠른 실행의 원본을 확인했다. 기존 라이선스가 있는 포트를 유지하고 프로젝트 상태·접근 이름·테마에 연결한다. 기존 업로드·메뉴·로그인/가입·토스트도 보존한다.

Stageshow: 기존 static-card 기반400×300 정적 제작 흐름을 재사용한다. 창·앞쪽 클립의 구도·크롭·선택 제목을 유지하며 팔레트를 맞춘다. 실제 앱 기능을 회색 막대나 가짜 커서로 대체하지 않는다. 사용자 데스크톱 지시가 모바일 compact 검수보다 우선한다.

Agency 역할: 읽기 전용 UX/구조 검토 → UI Designer의 공통 토큰·표면 설계 → Frontend Developer의 레일·대시보드 통합과 시각 요소 구현 → 별도 Evidence Collector의 실제 캡처 검토로 인계한다. 각 단계는 이 계약과 기존 기능 검수를 공유한다.

## 완료 기준

기존 단위 시험·TypeScript·프로덕션 빌드. 기존 제작 흐름 회귀와 새 레일/대시보드 상호작용. 1280·1440·1920px, 라이트·다크의 가로 넘침·초점·문구 가독성을 확인한다. Stageshow는 정적 --still --gate를 사용하고 애니메이션 검수로 보고하지 않는다.
