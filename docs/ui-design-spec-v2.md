# 호루박 UI 설계명세 v2

승인 기준: 2026-11-05 대화의 v2 계획과 후속 선택. 구현 기준 문서이며, 구현·검증 결과는 별도 검수 기록으로 구분한다.

## 1. 목표와 범위

차분한 작업 도구 형태로 전체 UI를 통일한다. 실제 가능한 작업과 다음 행동을 명확히 드러내며 대표 제작 흐름부터 구현·검증한다.

- 데스크톱 창 너비 1280px 이상만 지원한다. 작은 창은 동일 배치와 가로 스크롤을 사용한다. 모바일 전용 메뉴·재배치·터치 설계는 구현하지 않는다.
- 브랜드명 호루박, 중립적인 배경과 파란색 포인트를 사용한다. Emil 기준을 공통 적용하고 유용한 Lucian 동작과 라이선스를 보존한다.
- 현재는 브라우저 데모다. 실제 인증·AI·업로드·서버 저장·MP4 렌더링 구현은 이번 UI 변경에 포함하지 않는다.
- 검수는 본인 기준이다. 에이전트의 기능·브라우저 검증과 사용자의 직접 검수, 처음 쓰는 사람의 사용성 검증을 구분한다.
- 기존 경로·Project/EditState·브라우저 저장 키·원본 초 단위 시간·팀 API 계약을 유지한다.

## 2. 공통 디자인

| 항목 | 라이트 | 다크 |
|---|---|---|
| 배경 | #F6F7F9 | #111318 |
| 표면 | #FFFFFF | #191C22 |
| 보조 표면 | #F0F2F5 | #222730 |
| 본문 | #202329 | #EDF0F5 |
| 보조 글자 | #66707F | #A6AFBD |
| 구분선 | #E2E6EC | #323946 |
| 입력 경계 | #8993A1 | #657083 |
| 선택 배경 | #EAF1FE | #1C2C46 |
| 링크 | #1B64DA | #6CA6FF |

- 주요 버튼은 #1B64DA와 흰 글자, 포커스는 #3182F6를 사용한다.
- 시스템 글꼴, 본문 14/22px, 보조 12/18px, 제목 24/32px·600을 사용한다.
- 버튼 높이 40px, 입력 44px. 모서리는 버튼/입력 8px, 카드 10px, 대화상자 12px다.
- 콘텐츠 여백 24px, 기본 간격 16px. 기본 표면은 구분선으로 나누고 그림자는 메뉴·대화상자에 제한한다.
- 로그인 이후 사이드바 216px·상단바 56px의 단일 셸을 사용한다. 사이드바는 내 프로젝트·즐겨찾기·편집 결과다.
- 상단에는 현재 화면·빠른 실행·데모·테마·계정 메뉴를 둔다. 계정 버튼은 즉시 로그아웃하지 않는다.
- 신규 등록 CTA는 프로젝트 화면에 두고 사이드바에 중복하지 않는다.

## 3. 화면과 대표 흐름

| 화면 | 구성 |
|---|---|
| 로그인·가입 | 독립 중앙 384px 양식. 소개 영역 없이 입력·오류·전환·샘플 시작, 짧은 데모 안내 |
| 프로젝트 | 제목/등록→최근 작업 한 줄→검색·장르·정렬·보기 전환→3열 카드. 필터 중 최근 작업 숨김 |
| 등록 | 최대760px, 파일/URL/샘플→장르→이름. 로컬 미리보기·주소만 저장·샘플의 차이를 입력 위치에 표시 |
| 처리 | 최대680px, 현재 상태·데모 진행률·단계·가능한 행동. 실패/취소에서 현재 단계·스피너 정지 |
| 편집 | 260px 후보/전사 + minmax(400px,1fr) 미리보기/타임라인 + 280px 설정, 간격16px |
| 결과 | 최대1000px, 미리보기와 구간·다운로드·다시 편집의 2열 |

편집 미리보기는 9:16·높이 최대480px, 후보/전사 목록만 최대560px 내부 스크롤로 둔다. 문서 세로 스크롤을 허용한다. 일반 콘텐츠는 최대1200px이며 편집은 남은 폭 전체를 사용한다.

대표 흐름: 샘플 열기→후보 선택→추천 근거와 원본 전사→맥락 비교→명시적 보정 적용→되돌리기→결과 확인→SRT/JSON 다운로드.

- 후보·전사 선택, 보정, 되돌리기는 재생을 멈추고 원본 시간으로 이동한다.
- 선택 구간·근거·맥락 경고를 찾기 쉽게 배치한다. 모바일 이동 버튼 등 검증되지 않은 추가 조작은 만들지 않는다.
- 원본 재연결은 편집값을 보존한다. 새 길이와 기존 구간의 충돌은 자동 변경 대신 오류로 드러낸다.
- 프로젝트 카드는 제목 두 줄·전체 이름 확인, 장르·출처·상태·수정일을 제공한다. 썸네일이 없으면 장르 아이콘을 사용한다.

## 4. 상태·상호작용·연동

| 기존 상태 | 화면 문구 |
|---|---|
| processing | 화면 준비 중 |
| ready | 편집 준비 |
| completed | 편집 확인됨 |
| failed | 준비 실패 |
| cancelled | 준비 취소 |

- 상태와 출처·원본 연결·분석/렌더 가용성은 별개다. 공통 UI 표시 함수에서 계산하며 영속 필드를 추가하지 않는다.
- 샘플 분석을 실제 분석으로 표시하지 않는다. 직접 영상의 빈 후보/전사는 분석 연결 전으로 설명한다.
- 원본 미연결은 다시 연결, URL은 주소만 등록, 길이 미확인/잘못된 구간은 이유와 제한을 표시한다.
- 저장 오류 중에는 저장됨 문구를 표시하지 않는다.
- 편집의 주요 행동은 편집 확인, 확인창 이동은 결과 확인이다. completed 기록이 영상 렌더링을 뜻하지 않게 한다.
- 샘플 SRT는 유효한 샘플에서만, JSON은 유효한 편집 구간에서 제공한다. JSON의 rendered:false와 source_seconds를 유지한다.
- MP4는 영상 출력 연결 전 정보 행으로 표시한다. 미연결/실패를 샘플 성공 화면으로 대체하지 않는다.
- 검색·탭·키보드·빠른 실행은 즉시 동작한다. 연출용 700/650/500ms 지연·가입 포커스 지연·오류 흔들림·반복 장식·순차 등장을 제거한다.
- 포인터 누름120ms, 간헐적 메뉴/대화상자160ms만 사용하고 reduced-motion에서는 이동을 제거한다. 고빈도·키보드 조작은 애니메이션하지 않는다.
- 포커스 표시·Escape·대화상자 종료 후 포커스 복원을 유지한다.
- 토큰은 단일 정의, 공통/컴포넌트 스타일은 책임별 소유로 정리한다. 추가 덮어쓰기 레이어를 누적하지 않는다. CSS 파일 개수만으로 충돌을 단정하지 않는다.
- 신규 패키지·외부 글꼴·생성 이미지를 추가하지 않는다.

역할 전달: UX Architect의 화면/상태 계약→UI Designer의 시각 계약→Frontend Developer의 구현→Evidence Collector의 증거 검토. 각 작업 단위는 분석→계획→구현→검증→보고 순서로 진행한다.

## 5. 검수와 확장 조건

- 대표 흐름 구현 직후 다른 화면 확장 전에 기능 검수를 수행한다. 본인 직접 검수는 에이전트 검증과 별도로 남긴다.
- 1280×800·1440×900·1920×1080, 밝음/어두움에서 필수 조작 가림·가로 넘침·대화상자 잘림을 확인한다.
- 기존12개 테스트·공통 표시/다운로드 규칙 테스트·TypeScript·프로덕션 빌드를 실행한다.
- 검색/필터 복구/정렬/보기/즐겨찾기/이름변경/삭제취소, 후보/전사/보정/undo/구간오류/크롭을 확인한다.
- 로컬MP4·새로고침 후 원본 재연결·편집 유지·다운로드 파일 내용을 확인한다.
- 빈 목록·검색 없음·긴 제목·원본 없음·저장 오류·실패/취소·키보드 조작을 확인하고 미실행 항목은 명시한다.
- 후보 탐색/맥락 비교 복귀가 더 어려워지거나, 샘플/실제 분석·편집 확인/MP4 출력을 구별하기 어렵거나, 기능 회귀/필수 조작 가림이 발생하면 확장을 멈추고 수정한다.
- 문구·지연 수정만으로 목표를 충족하면 불필요한 추가 구조 변경을 줄인다. CSS 효과는 중복 규칙·변경 영향·원인 추적 근거로 별도 평가한다.
- 완료 보고는 UI 구현·에이전트 검증·본인 검수·서버 미연결·초보 사용자 사용성 미검증을 구분한다.
