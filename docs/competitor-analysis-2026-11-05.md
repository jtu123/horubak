# 호루박 경쟁 분석 및 개선안
작성·확인일: 2026-11-05 (KST) · 대상: OpusClip / Vizard · 현재 저장소 기준

## 1. 판단 요약

호루박의 가장 큰 격차는 **실제 영상의 등록→분석→검토→MP4 완성 흐름과 그 품질을 입증할 자료가 없는 점**이다. 화면 v2는 제작 도구의 골격을 갖췄지만 현재는 브라우저 데모다. 서버 연결과 한국어 품질 평가를 병행하는 좁은 구현이 우선이다.

차별화 후보는 **한국어 지식 콘텐츠에서 의미를 바꾸는 누락을 찾아, 원본 근거와 보정 차이를 사람이 확인하게 하는 제작 흐름**이다. 아직 검증된 경쟁 우위는 아니다. Vizard도 클립 완결성·추천 이유·중복 제거를 안내하므로 “맥락을 고려한다”만으로 차별성을 주장하기 어렵다. [Vizard 모델 설명](https://vizard.ai/blog/most-ai-clipping-tools-cut-videos-vizards-ai-clipping-model-v2-edits-them)

이 문서의 제안은 기존 담당을 바꾸지 않는다. 권준한은 SFR-003·004·005·007, SIR-001, 전체 웹 UI를 맡고, 팀원 기능은 계약·연결·공동 검증으로 다룬다. 다른 팀원의 별도 저장소 구현 상태는 미확인이다.

## 2. 조사 방법과 한계

- 현재 소스·README·연동 문서·v2 검수 자료를 읽고 실제 동작, 샘플, 계획, 미확인을 구분했다.
- 경쟁사 공식 사이트·가격·개발자·지원 문서 17개를 조사했다. 공개 홈페이지는 브라우저로 직접 확인해 스크린샷을 남겼다.
- 경쟁사 가입·유료 편집기 사용·개인 영상 업로드·동일 영상 처리 성능 비교는 하지 않았다. 편집 기능 비교는 공식 문서에 근거한다.
- 홍보하는 정확도·속도·바이럴 효과·보안 인증은 이번 조사에서 재현하거나 감사하지 않았다.
- 전체 가능한 결함을 보증하는 실사는 아니다. 접근 가능한 증거에서 중요한 격차를 최대한 분류했다.
- Council은 Karpathy·Rams·Torvalds 관점의 3라운드 검토다. 모두 같은 제공자의 AI 에이전트이며, 실제 인물 참여나 독립된 다중 모델 검증을 뜻하지 않는다.
- 모바일 전용 UI 제외·1280px 이상 지원은 기존 합의다. 시장 접근성의 제약으로 기록하되 이번 개인 구현 범위에 추가하지 않는다.

**표시 기준:** 확인 = 코드/문서에서 확인, 계획 = 아직 구현 완료 근거 없음, 추론 = 영향·개선에 대한 분석, 미확인 = 접근하거나 시험하지 않음.

추가 계약 위험: 편집 화면의 단일 자막 문구와 SRT 생성에 쓰는 샘플 발화 텍스트는 별개다(Results.tsx:19, lib.ts:25). 현재는 샘플 출력으로 표시하지만, 실제 연결에서는 전사·자막 큐·미리보기·렌더가 같은 편집 버전을 사용해야 한다.

## 5. 시스템·AI·편집에서 부족한 부분과 개선

### 5.1 실제 처리 흐름과 결과의 일관성 — P0

**영향:** 사용자가 자신의 영상을 넣어도 분석 후보와 완성 MP4를 얻지 못한다. 현재 UI 개선만으로 이 격차가 해소되지는 않는다(H1·H5·H6).

**개선:** 권리가 확보된 원본 하나와 인증 사용자 둘을 사용해 실제 업로드→작업→STT→후보→검토→저장→렌더를 연결한다. 첫 범위는 연속 구간 하나, 9:16, 클립 하나여도 된다. URL 수집·복잡한 자막 스타일·다중 장면은 뒤에 붙여도 된다. 단, 실패를 샘플 성공으로 대체하지 않는다.

**완료 증거:** 처리 이력, 원본·분석·편집 버전, 사람이 검토한 MP4와 자막, 새로고침 후 복원, 사용자 간 접근 차단 결과가 남아야 한다. 다운로드 버튼 활성화만으로 완료하지 않는다.

### 5.2 시간·버전·다중 클립 데이터 — P0/P1

현재 단일 edit 구조는 여러 후보를 각기 보정·저장·출력하기 어렵다(H4). 저장 버전 계약은 있으나 UI와 실제 결과에 연결되지 않았다(H7).

**제안 계약:**

| 개념 | 필요한 내용 |
|---|---|
| 원본 | media ID, 길이, 원본 시간 기준, 가로·세로·회전·프레임 정보, 입력 버전 |
| 전사 | 발화 ID, 어절 ID·시간, 화자 ID, 텍스트 수정 버전, 품질 경고. 모델별 신뢰도 의미 구분 |
| 후보 | 원본 구간, 추천 이유·근거 발화, 장르/목표, 후보군 내 순위·중복 정보 |
| 맥락 검토 | 누락 유형, 근거 발화 ID, 심각도, 보정 전후 구간, 미해결 이유, 사용자 결정 |
| 화자/얼굴/크롭 | 시간 구간별 track ID, 정규화 박스, 화자 대응 근거·불확실성, 수동 override |
| 클립 | clip ID, 원본 구간 목록, 자막 cue 목록, 시간별 크롭/레이아웃, 편집 버전 |
| 작업·출력 | 입력/분석/편집 버전, 상태·단계·실패 코드, 요청 ID, 산출물 검사 결과 |

1차는 구간 목록 길이 1로 제한해도 된다. 비연속 편집을 도입할 때는 삭제 구간을 반영한 **원본 시간↔출력 시간 매핑**을 정의한다. 전사 수정과 영상 컷을 같은 동작으로 암묵 처리하지 않는다. 과거 작업의 늦은 응답이 최신 편집을 덮어쓰지 않게 한다.

### 5.3 SFR-003 한국어 STT — P1, 단 P0 연결과 병행

계획에 STT 도구는 있으나 현재 정확도 자료가 없다. 한국어 조사·띄어쓰기만으로 평가가 흔들리므로 원문 CER와 정규화 CER를 함께 기록한다. 전문용어·고유명사·숫자/단위·영어 혼용·부정 표현은 별도 오류표를 둔다.

어절 시간, 원본 정렬, 무음·겹침·잘 안 들리는 부분을 전달하고 수정 가능하게 한다. 도구가 반환하는 confidence를 서로 다른 모델 사이의 확률로 비교하지 않는다. 모델 크기·장치·설정은 동일 표본에서 품질·시간·메모리를 측정해 결정한다. 현재 PC 사양만으로 공용 서버 처리량을 약속하지 않는다.

### 5.4 SFR-004 하이라이트 후보 — P1

“30~60초, 3~5개”만으로 좋은 후보를 정의하기 어렵다. 강의의 개념·예시, 연설의 주장·조건, 팟캐스트의 질문·답변을 평가 기준으로 구체화한다. 문장 완결성, 중복, 원본 앞뒤 의존성, 자막 가능성, 화자 전환을 함께 검사한다.

후보가 부족하면 이유를 반환한다. 목표 길이에 맞추느라 조건을 자르지 않는다. 목표 초과 보정안은 사용자 검토 상태로 제시하고, 무조건 길이를 늘리거나 자동 승인하지 않는다. 숫자 점수는 후보군 내 우선순위로 표시하거나 설명 없는 점수를 숨긴다. 외부 조회수 확률로 명명하지 않는다.

사용자는 흥미·정확성·길이·구도 때문에 후보를 채택/수정/거절할 수 있어야 한다. 이 기록으로 추천 개선과 가치 검증을 함께 한다.

### 5.5 SFR-005 의미 보존 — 핵심 차별화 실험

“이 약이 좋다”만 남기고 “특정 조건에서만”을 빼거나, 질문을 지워 답변의 대상이 바뀌는 경우를 다룬다. 다음 유형을 각각 검사한다.

- 조건·예외·한정, 부정·반전
- 지시어·대상·인물, 숫자·단위·기간
- 질문/답변 관계, 인용과 본인 주장 구분
- 문장·논증의 끝, 앞뒤 연결과 반례

경고마다 **누락 근거→왜 의미가 바뀔 수 있는지→원본 재생→보정 차이→사용자 선택**을 연결한다. 보정 뒤 새로운 손실·다른 화자 포함·길이 초과를 재검사한다. 의미 변형이 해결되지 않으면 위험을 남기거나 다른 후보를 제시한다.

발화 ID 존재·시간 범위·구간 길이는 서버에서 검증한다. 전사 안의 명령문은 분석 대상 데이터로 취급하고 시스템 동작 지시로 실행하지 않는다. 자동 판정은 사실의 진위를 보증하는 기능으로 소개하지 않는다.

### 5.6 SFR-007 화자·얼굴·크롭 — P1

현재는 한 위치의 수동 크롭이다(H4·H5). 실제 기능은 화자 분리, 얼굴 추적, 화자↔얼굴 대응, 시간별 프레이밍, 사용자 수정으로 나뉜다. 얼굴 검출만으로 말하는 사람을 확정할 수 없다.

화면 밖 발화·중첩 발화·슬라이드만 표시·컷 전환·작은 얼굴·두 사람 교차를 시험한다. 확실하지 않으면 전체 화면 또는 수동 선택으로 돌아간다. 컷 전환을 넘겨 얼굴 ID를 잘못 이어 붙이거나 화면이 계속 흔들리지 않게 한다. 자료 레이아웃/OCR 판단은 담당 팀원에게 전달한다. 개인의 신원 확인 기능은 요구하지 않는다.

경쟁사도 다인 영상 오인식을 문서화한다. 따라서 “자동 추적 제공”보다 **틀렸을 때의 표시·복구·검증**이 중요하다. [Vizard 오인식 안내](https://help.vizard.ai/en/articles/14671161-why-does-the-ai-frame-the-wrong-person-in-multi-person-videos)

### 5.7 편집·자막·출력 품질 — P1/P2

- 실제 오디오 기반 파형과 키보드/포인터 트림을 연결하거나 작동하지 않는 드래그 표시를 제거한다.
- 전사 수정, 자막 cue 수정, 영상 구간 삭제의 영향을 명확히 나눈다.
- 자막 줄바꿈·동시 표시량·화면 안전 영역·숫자/기호·글꼴 대체를 실제 출력으로 확인한다.
- 미리보기와 렌더의 crop·자막·시작/끝·오디오가 같은 버전을 사용하게 한다.
- 렌더는 파일 존재뿐 아니라 길이·해상도·코덱·오디오/자막 싱크·첫/마지막 프레임을 검사한다.
- 여러 후보를 별도 클립으로 저장하는 기능을 먼저 설계하고, 복잡한 비연속 조합·일괄 출력은 다음 단계로 둔다.
- undo/redo와 저장 버전 복원은 구분하고, 탭 종료·네트워크 끊김·동시 수정 충돌에서 사용자 편집을 보존한다.

## 9. 평가 설계와 잠정 통과 기준

다음은 **제안**이며 측정 결과나 검증된 품질 보장이 아니다. 실제 샘플과 인력·장비를 보고 착수 시 기준을 확정한다.

### 표본·실험

1. 권리 확보한 강의·연설·팟캐스트 각 3편(초기 9편, 예: 10~20분)을 구성한다. 장르 외 잡음·겹침·슬라이드·다인/얼굴 없음을 교차 태그한다.
2. 같은 원본의 구간을 튜닝과 평가에 나누지 않는다. 개발 표본과 별도 보류 표본을 원본 단위로 분리한다. 표본 수가 작다는 한계를 명시한다.
3. 사람이 전사·중요 용어·의미 누락·허용 경계·크롭 대상 정답을 기록한다. 일부는 두 평가자가 독립 판정 후 불일치를 조정한다.
4. 후보 평가는 출처를 가린 순서로 원본과 함께 평가한다. 자동 제안 전/후와 수동 제작 기준을 비교한다.
   맥락 검토는 같은 후보의 기본 검토와 경고·보정 지원 검토를 비교한다. 의미 손실 감소와 총 수정 시간을 함께 기록해, 경고가 많아진 사실을 품질 개선으로 오인하지 않는다.
5. 버전·프롬프트·모델 설정·장치·처리 시간·실패 비용을 남긴다. 같은 표본으로 측정하고 결과가 나쁘면 숨기지 않는다.
6. 경쟁사 직접 비교는 별도 실험 범위로 남긴다. 권리가 확보된 동일 원본, 요금제·제품·설정·일자를 맞추고 별도 승인 범위에서 수행한다. 이번 조사에는 해당 결과가 없다.

## 10. 권장 제품 방향과 보류 범위

**초기 가설:** “한국어 지식 콘텐츠에서 원본 의미를 확인하면서 게시 가능한 하이라이트를 만드는 도구.”

진행 순서는 다음과 같다.

1. **실제 최소 제작:** 한 원본·한 클립·한 출력 형식으로 서버 권한과 결과까지 연결한다. 동시에 한국어 평가 자료를 만든다.
2. **근거 있는 검토:** 어절 시간·후보 완결성·구조화된 맥락 경고·화자 대응의 불확실성과 수동 복구를 구현한다.
3. **반복 제작:** 실제 채택·수정 비용을 본 뒤 다중 클립·브랜드·일괄 출력 등 가장 필요한 효율 기능을 추가한다.

생성형 B-roll·아바타·음성 복제·모든 소셜 예약·전문 다중 트랙·SSO·과금·모바일 전용 UI는 1차 기능 동등화 목표에서 보류한다. 고객 요구나 평가 목적이 생기면 다시 판단한다. 기존 계획의 OCR·자연어 편집도 담당 팀원과 연결하되, 이것들이 첫 실제 영상 완성을 불필요하게 막지 않도록 범위를 분리한다.

경쟁사가 제공하는 기능 전체를 세 명이 따라가는 전략은 유지비와 검증 범위를 크게 늘린다. 반대로 학술적 평가만 계속하고 실제 제작을 연결하지 않으면 고객의 수정·완주 비용을 알 수 없다. 두 작업을 작은 범위에서 병행하는 것이 이번 권고다.
