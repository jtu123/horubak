# SFR-001 원본 영상 입력 및 등록 구현 코드 설명서

## 1. 구현 목적

SFR-001은 강의·연설·팟캐스트 영상 파일 또는 지원 URL을 등록하고, 입력된 영상의 유형과 처리 조건을 확인하는 기능이다.

현재 구현에서는 React 기반 프론트엔드에서 영상 입력 정보를 전달하고, Node.js + Express 기반 백엔드에서 파일을 전달받아 영상 정보를 처리하는 구조로 구현하였다.

### 구현 대상

- MP4/MOV 영상 파일 업로드
- 영상 입력 정보 전달
- 영상 장르 선택
  - Lecture
  - Speech
  - Podcast
- 영상 파일의 기본 정보 확인
- 프로젝트 생성 요청 처리
- 영상 파일 저장 및 후속 처리를 위한 구조 구성

# 4. `app.ts`

## 역할

백엔드 서버의 시작점이다.

Express 서버를 생성하고 CORS, JSON 요청 처리, API Route를 등록한다.

주요 구조:

```ts
import express from "express";
import cors from "cors";

const app = express();
```

Express 애플리케이션을 생성한다.

### CORS 설정

```ts
app.use(
  cors({
    origin: "http://localhost:5173",
  })
);
```

React 프론트엔드에서 실행되는 요청을 백엔드가 허용하기 위해 사용한다.

현재 프론트엔드는 개발 서버 기준으로 `5173` 포트를 사용한다.

### JSON 요청 처리

```ts
app.use(express.json());
```

JSON 형태로 전달되는 프로젝트 정보를 처리할 수 있도록 설정한다.

### Health Check API

```ts
app.get("/api/health", (_req, res) => {
  res.json({
    success: true,
    message: "Backend server is running.",
  });
});
```

백엔드 서버가 정상적으로 실행되고 있는지 확인하기 위한 테스트 API이다.

브라우저에서:

```text
http://localhost:8080/api/health
```

로 접근하여 서버 상태를 확인할 수 있다.

### 프로젝트 API 연결

```ts
app.use("/api/projects", projectRoutes);
```

프로젝트 관련 요청을 `project.routes.ts`로 전달한다.

# 5. `project.routes.ts`

## 역할

HTTP 요청 URL과 실제 처리 함수를 연결하는 역할을 담당한다.

```ts
const router = Router();
```

Express Router를 생성한다.

### 영상 파일 업로드 설정

```ts
const upload = multer({
  storage: multer.memoryStorage(),
  limits: {
    fileSize: 4 * 1024 * 1024 * 1024,
  },
});
```

`multer`를 이용하여 파일 업로드를 처리한다.

현재 최대 파일 크기는 4GB로 설정되어 있다.

### 프로젝트 생성 API

```ts
router.post(
  "/",
  upload.single("file"),
  createProject
);
```

클라이언트가 다음 주소로 POST 요청을 보내면:

```text
POST /api/projects
```

프로젝트 생성 처리가 실행된다.

처리 순서는 다음과 같다.

```text
POST /api/projects
       ↓
upload.single("file")
       ↓
createProject()
```

`upload.single("file")`은 multipart/form-data로 전달된 영상 파일을 받아 `req.file`에 저장한다.

# 6. `project.controller.ts`

## 역할

클라이언트에서 전달한 요청 데이터를 받아 서비스 계층으로 전달하고 결과를 HTTP 응답으로 반환한다.

```ts
export const createProject = async (
  req: Request,
  res: Response
) => {
```

Express의 Request와 Response를 이용한다.

### 요청 데이터 추출

```ts
const {
  projectName,
  genre,
  inputType,
  sourceUrl,
} = req.body;
```

프로젝트 이름, 장르, 입력 방식, URL 등의 데이터를 추출한다.

영상 파일은:

```ts
const file = req.file;
```

을 통해 가져온다.

### Service 호출

```ts
const result = await createProjectService({
  projectName,
  genre: genre as Genre,
  inputType: inputType as InputType,
  sourceUrl,
  file: file
    ? {
        originalname: file.originalname,
        buffer: file.buffer,
      }
    : undefined,
});
```

Controller에서 직접 영상 처리 로직을 수행하지 않고 `project.service.ts`에 처리를 맡긴다.

이렇게 하면:

```text
Controller = 요청/응답 처리
Service = 실제 기능 처리
```

로 역할을 분리할 수 있다.

### 성공 응답

```ts
return res.status(201).json({
  success: true,
  data: result,
});
```

프로젝트 생성이 정상적으로 처리되면 HTTP 상태 코드 `201`과 결과 데이터를 반환한다.

### 오류 처리

```ts
catch (error) {
```

오류가 발생하면:

```ts
return res.status(400).json({
  success: false,
  message:
    error instanceof Error
      ? error.message
      : "프로젝트 생성에 실패했습니다.",
});
```

오류 메시지를 클라이언트에 전달한다.

# 7. `project.service.ts`

## 역할

SFR-001의 실제 핵심 기능을 처리하는 Service 계층이다.

Controller에서 전달받은 프로젝트 정보를 바탕으로:

1. 입력값 확인
2. 파일 형식 확인
3. 영상 파일 저장
4. 영상 메타데이터 확인
5. 프로젝트 결과 반환

등의 처리를 담당한다.

Controller와 Service를 분리한 이유는 프로젝트 생성 로직이 Controller에 모두 들어가는 것을 방지하고 기능별 유지보수를 쉽게 하기 위해서이다.

# 8. `video.service.ts`

## 역할

영상 파일의 실제 미디어 정보를 확인한다.

영상 파일을 단순히 업로드하는 것뿐만 아니라 영상의:

- 재생 시간
- 해상도
- 영상 형식
- 비디오 스트림
- 코덱

등의 정보를 확인하기 위해 `ffprobe`를 사용한다.

### ffprobe 실행 구조

```text
영상 파일
   ↓
ffprobe
   ↓
영상 메타데이터
   ↓
JSON 형태로 반환
```

이를 통해 업로드된 영상이 실제로 처리 가능한 영상인지 확인할 수 있다.

# 9. `ffprobe-static.d.ts`

## 역할

TypeScript에서 `ffprobe-static` 모듈을 사용할 때 타입 정보를 찾을 수 있도록 선언한다.

일부 JavaScript 패키지는 TypeScript용 선언 파일을 제공하지 않기 때문에 별도의 `.d.ts` 파일을 작성하여 TypeScript 오류를 방지한다.

즉:

```text
ffprobe-static
      ↓
TypeScript가 모듈 타입을 알 수 있도록
      ↓
ffprobe-static.d.ts
```

구조로 사용한다.

---

# 10. `url.service.ts`

## 역할

영상 파일이 아닌 URL 방식으로 입력된 경우 URL을 확인하는 역할을 담당한다.

현재 구현에서는 URL의 기본적인 형식을 확인하고, 허용되지 않은 URL을 무조건 다운로드하지 않도록 처리하는 구조이다.

플랫폼별 실제 원본 영상 확보 기능은 추후 URL 공급자별 Adapter를 추가하여 확장할 수 있다.

# 11. `file.utils.ts`

## 역할

영상 파일 처리에 필요한 공통 기능을 별도로 분리한다.

예를 들어 파일 확장자 확인, 파일명 처리, 업로드 디렉터리 관리 등의 기능을 Service에서 분리하여 사용할 수 있도록 구성한다.

# 14. 현재 확인된 오류

현재 코드 작성은 완료되었으나 백엔드 실행 과정에서 Express Router 관련 오류가 발생하고 있다.

오류 메시지는 다음과 같다.

```text
TypeError: argument handler must be a function
```

현재 오류 발생 위치는:

```text
app.use("/api/projects", projectRoutes);
```

부분이다.

따라서 현재 단계에서는 **코드 작성은 완료되었지만 백엔드 실행 및 프론트엔드와의 실제 통합 테스트는 완료되지 않은 상태**이다.

팀원들과 개발 환경 및 Express Router 설정을 함께 확인하여 오류를 해결한 후 실제 영상 파일 업로드 테스트를 진행할 예정이다.

# 15. 향후 보완 사항

SFR-001 이후에는 다음 기능을 확장할 수 있다.

### 저장 기능

현재 로컬 파일 저장 구조에서 추후 객체 저장소를 사용할 수 있다.

```text
현재
로컬 uploads/original/

추후
Object Storage
```

### 데이터베이스

프로젝트 정보와 처리 상태를 PostgreSQL 등의 데이터베이스에 저장할 수 있다.

### URL 공급자 Adapter

플랫폼별 URL 처리 방식을 분리하여:

```text
URL
 ↓
Provider Adapter
 ↓
메타데이터 확인
 ↓
허용된 원본 확보
```

구조로 확장할 수 있다.

### SFR-002 연계

대용량 영상의 비동기 처리, 진행 상태, 취소, 재시도 등의 기능은 SFR-002에서 별도로 구현한다.

따라서 SFR-001에서는 **원본 영상의 입력·등록 및 기본 검증에 집중하고**, 대규모 비동기 처리 기능과 혼합하지 않는다.
